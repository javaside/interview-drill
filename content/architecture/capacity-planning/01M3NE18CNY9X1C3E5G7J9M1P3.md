扩容的兵器谱，**从便宜到贵、从快到慢**：

1. **软扩容（先想这个）**：缓存命中率从 50% 提到 90%，下游压力直接砍 80%——**不加机器解决容量问题**永远是第一优先级；同理异步化（同步变 MQ）、降级（非核心功能让路）；
2. **垂直扩**：单机 8C → 32C。**最快**（改配置重启）但**最贵**（单价非线性）且**有物理上限**（单机顶配就到头）——适合救急和量级未明的早期；
3. **水平扩**：加实例。前提是**无状态**——session 入 Redis、本机文件入对象存储、本地缓存注意一致性；有状态的服务加机器是灾难的开始；
4. **数据层扩**：读写分离（写主读从——读先扛不住的场景）→ 分库分表（写也扛不住）——**改造最重**（分片键/跨片查询/分布式事务全是债），见分布式大类；

**决策顺序**：降载（缓存/异步）→ 垂直（救急）→ 水平（常态）→ 数据层（最后）。**跳级是灾难**：还没做无状态化就上分库分表，等于同时背两个大改造的债。

**术语速查**：软扩容=不加机器的容量|无状态=水平扩的入场券|跳级=同时背两个改造

有状态服务的扩展（分片路由/一致性哈希——数据层水平扩的内功）。单元化架构（按用户分 Set 部署——异地多活的地基）。Serverless 的弹性档（按请求扩到零——长尾服务的成本解）。
