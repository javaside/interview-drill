工具调用是 Agent 的地基，关键认知：**模型从不执行任何东西，它只产出「调用意图」**——四步循环：

```
①应用：带工具清单（名字 + 描述 + 参数 JSON Schema）发起请求
②模型：判断需要工具 → 输出结构化意图 {name: "get_weather", arguments: {city: "上海"}}
③应用：自己执行（HTTP/SQL/函数）——权限、超时、重试全是应用的事
④应用：结果作为 tool 消息回填 → 模型读结果：够答了就总结，不够就再发起新调用
```

**两个决定成败的细节**：

- **工具描述就是模型的世界**：模型靠描述决定「何时用、怎么传参」——描述含糊（「查询数据」）或参数命名随意（a/b），调用质量立刻崩。**给工具写描述 = 给新同事写接口文档**：用途、适用时机、不适用时机、参数含义与格式、返回结构；
- **幻觉工具**：模型可能输出清单里没有的工具名或编造参数——schema 校验拦截 + 失败信息回喂让它重试，而不是直接崩。

**术语速查**：调用意图=模型只决策不执行|工具描述=模型眼中的接口文档|回填循环=结果进上下文再判断
