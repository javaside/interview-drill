**ReAct（Reason + Act）= 把「单发问答」变成「带观察的循环」**：

```
循环开始
  思考：问题要查最新股价，我先调搜索
  行动：search("AAPL 股价")
  观察：<tool 返回 231.5>
  思考：拿到价了，用户还问市盈率——再查财报
  行动：query_db("SELECT pe FROM ...")
  观察：<tool 返回 31.2>
  思考：信息齐了
  最终答案：AAPL 现价 231.5，市盈率 31.2……
循环结束
```

**与普通 function calling 的关系**：工具调用是**机制**（怎么发起一次调用），ReAct 是**模式**（怎么把多次调用组织成循环）——function calling 管「一次握手」，ReAct 管「整个会话的节奏」。

**循环的刹车系统**（Agent 工程化的核心）：

- **最大步数**（如 10 步）——防模型在「查→不够→再查」里打转；
- **预算上限**——token 与工具调用次数都要有账本；
- **重复检测**——同样的工具+同样的参数出现两次，说明它卡住了，强制换路或上报；
- **反思变体**（Reflexion）：每步后追加「刚才这步达到目的了吗」的自评——把死循环变成「早发现早改道」。

**术语速查**：思考-行动-观察=循环的三拍|刹车系统=步数/预算/重复检测|单发变循环=Agent 与 chatbot 的分水岭

<!--advanced-->
轨迹（trajectory）评测——不只评最终答案，还评中间步骤的质量。子目标分解（任务拆给子 Agent，各自 ReAct）。工具调用失败的观察反馈设计（错误信息写给模型看——可恢复的错误要给重试提示）。
