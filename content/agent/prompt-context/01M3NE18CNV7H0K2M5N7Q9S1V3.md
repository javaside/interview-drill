两层 prompt 是**宪法与提案**的分工：

| 层 | 放什么 | 特征 |
|---|---|---|
| **system** | 角色定位、能力边界、输出格式契约、安全红线、兜底行为 | **恒定**，一次写好全局复用 |
| **user** | 本次的具体输入、临时要求、上下文材料 | **多变**，每请求都不同 |

**为什么这么分**：①**优先级**——两层冲突时 system 通常胜出，所以安全规则和格式约束必须放 system（放 user 里可被用户的「忽略之前的要求」冲掉）；②**缓存友好**——prompt cache 按**前缀**命中：system 不变放头部，命中缓存的部分按折扣计费且省 prefill 时间；③**可维护**——全局规则一处改，不用每个调用点都记得同步。

**system prompt 三段式**：身份与边界（你是谁/只做什么）→ 输出契约（格式定义+一两个示例）→ 拒绝与兜底（不给答案时说什么、拿不准时怎么做）。

**术语速查**：宪法与提案=恒定与变化|前缀缓存=不变的部分打折|兜底行为=失败路径也是设计

<!--advanced-->
system prompt 抽取攻击与防（角色扮演诱导——分层信任与输出过滤）。多轮中 system 的持续约束衰减（长对话后重申关键规则）。prompt 版本化管理与回归评测（prompt 也该有 CI）。
