**Guardrail 不是「一个过滤器」，是三道闸的流水线**：

```
输入闸：意图分类（违规/越权/注入特征）→ 拦截、改写或放行
过程闸：工具调用白名单、检索范围限定、步数与预算上限
输出闸：schema 校验（结构合法才交付）、PII 脱敏、关键事实抽检
```

**各闸的典型器件**：输入侧用**小模型分类器**（快且便宜——「这段输入是否含隐藏指令/是否越权请求」）+ 规则正则（明显的攻击模式）；过程闸就是 Agent 的权限系统（上一张卡）；输出侧 schema 校验拦格式崩坏、正则拦 PII 外泄、抽样 judge 拦事实性胡说。

**误杀与漏杀的平衡**是运营核心：闸门规则**可配置、可灰度、有白名单**——新规则先小流量，观察误杀案例再放量；**拒答要给出口**（「这个问题我不能答，但可以帮你…」）——拦下用户但给出路，护栏才不是体验黑洞。

**放哪**：通用闸（PII/违规词/注入特征）放网关统一；业务闸（金融话术合规）放应用层——与 LLM 网关的职责分层一致。

**术语速查**：三道闸=进/程/出|可灰度=误杀可运营|拒答给出路=护栏的体验底线
