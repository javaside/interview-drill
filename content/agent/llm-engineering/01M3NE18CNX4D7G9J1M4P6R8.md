LLM 应用的可观测比传统服务多一维：**不只是「快不快」，还要「答得好不好」**。三层：

- **Trace（链路）**：一次请求从头到尾——prompt 版本号、检索召回了哪些块（相似度分数）、每次工具调用的入参出参与耗时、最终答案、总 token 与延迟。**最容易漏记的是 prompt 版本与检索明细**——没有它们，坏答案无从归因（是 prompt 改坏了？检索坏了？还是模型抽风？）；
- **指标（聚合）**：延迟分位、token 成本、失败率之外，LLM 特有指标——**拒答率**（guardrail 过狠）、**引用命中率**（答案挂了几条出处）、**人工抽检合格率**；
- **质量回流**：用户点踩/纠错按钮 + 定期抽样人工标注——线上坏例**沉淀进评测集**，形成「线上发现 → 评测集收录 → 下次回归拦截」的闭环。这是 prompt/模型迭代不翻车的安全网。

**质量缓慢劣化**最难抓（没有报错、指标平稳）：数据分布漂移（用户开始问新话题）、上游模型静默升级、检索库内容腐化——靠**定期跑金标评测集**（周级）对比基线，别只看实时大盘。

**术语速查**：prompt 版本=归因的第一线索|点踩回流=用户的差评是免费标注|金标周跑=劣化的体温计
