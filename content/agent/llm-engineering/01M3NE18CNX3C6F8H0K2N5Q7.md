业务直连各家 API 的问题在规模化那天爆发：密钥散落、每家 SDK 不同、某家宕机全局故障、成本没人看得见。**LLM 网关收口五件事**：

- **统一出口**：OpenAI/Anthropic/本地模型统一成一个接口——业务写一次，**换模型、换供应商、故障切换都只是网关配置**（供应商涨价/限流/宕机在生产是常态，不是意外）；
- **路由**：按任务类型（分类走小模型）、按成本（超额切便宜档）、按可用性（超时降级到备用家）动态选——「模型分级」策略的落地点；
- **治理**：密钥集中（业务侧零密钥）、按团队/功能的**配额与限流**（防一个业务拖垮预算）、全量审计日志（合规与排障）；
- **能力沉淀**：prompt 前缀缓存、guardrails（注入防护/输出校验）统一在网关做——业务侧不用每家都实现一遍；
- **度量**：延迟/成功率/token 成本按业务维度出账——「哪个功能花了多少钱、质量如何」一张报表。

**自建 vs 开源**：LiteLLM/OpenRouter 起步；特殊合规（全内网）或深度定制（自有路由策略）再自建薄层。

**术语速查**：统一出口=业务零感知换模型|路由=分级的落地|成本出账=看得见才管得住
