先把延迟拆成**两个不同的病**：

```
TTFT（首 token 延迟）——用户看到第一个字之前：
  prefill 长prompt 的计算 + 队列排队 + 模型负载
TPOT（每 token 间隔）——字与字之间：
  decode 的访存速度 + 输出长度
```

**TTFT 优化**（体感的关键）：缩短 prompt（上下文瘦身）、**prompt 前缀缓存命中**（prefill 直接跳过）、供应商就近 region、避开高峰限流。

**TPOT 优化**：换小模型（decode 快数倍）、限制输出长度（max_tokens + prompt 要求简洁——**要一句话别让它写三段**）、输出结构约束。

**并行化**：串行链路里的每一段独立开销都在叠加——多路检索并发（向量+全文同时发）、多文档摘要 map-reduce（N 篇并发）、无依赖的工具调用一次批量发起。

**体感兜底**（延迟物理上压不动时）：流式让「快」感知提前；骨架先渲染（先出小标题再逐段填）；进度反馈（「正在检索 3 个来源…」）——**等待有解释，焦虑减一半**。

**术语速查**：TTFT 与 TPOT=两种病两种药|prefill 跳过=缓存的延迟红利|体感优化=改不了速度就改感受
