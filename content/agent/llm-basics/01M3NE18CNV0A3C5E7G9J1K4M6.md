把 LLM 想成一个**永远在玩「接龙」的机器**：给它一串 token（模型的最小文字单位），它不产出「答案」，而是产出**全词表的概率分布**——下一个字是「猫」的概率 32%、「狗」18%、「鱼」9%……采样策略挑一个，拼回句尾，再来一遍。直到挑中「结束符」。

三个工程要点：

- **token ≠ 字**：常见词整块一个 token，生僻字拆成 2-4 块——所以「计费/上下文长度」都按 token 算，中文普遍比英文费 token；
- **KV 缓存是增量的**：已生成的前缀算过的注意力中间结果（K/V）缓存复用，每步只算新 token——这是吞吐的生命线，也是「长上下文贵」的根源（缓存随长度线性涨）；
- **没有回头路**：选错的 token 已进上下文，模型会「认真地把错话圆下去」——这就是幻觉滚雪球的机制，也是「先规划再写」类 prompt 策略的动因。

**术语速查**：自回归=用自己产的字接龙|词表概率分布=接龙的完整候选名单|KV 缓存=算过的不重算
