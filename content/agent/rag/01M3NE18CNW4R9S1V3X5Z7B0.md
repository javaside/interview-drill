RAG 排查的铁律：**先归因，后动刀——别一上来就换模型改 prompt**。两步定位法：

```
①检索层体检：准备金标问答集（问题 + 标准答案所在块）
  对每个问题看：top-k 检索结果里有没有正确块？
  召回率低 → 病在检索层

②生成层体检：跳过检索，把正确块手动塞进 prompt
  依然答错 → 病在生成层（模型没用好资料）
  能答对   → 生成层没问题，全怪检索
```

**检索层常见病**：分块斩断语义（定义与定义体被切开）｜只有向量路，精确词（型号/错误码）检不回｜**库里有旧版本**（新旧文档同时在库，检回上季度的政策）｜top-k 太小漏掉正确块。

**生成层常见病**：资料太多太长，正确块被稀释（迷失中间）｜prompt 没约束「仅依据资料」——模型用参数知识抢答｜资料与问题间接相关，模型没建立连接（缺一步改写或重排）。

**修复后必跑回归**：金标集上召回率与端到端正确率两条线——RAG 是系统工程，每次调参都可能按下葫芦浮起瓢。

**术语速查**：两步归因=先查检回没再查用上没|金标集=带标准出处的问答对|旧版本污染=库里最阴的病
