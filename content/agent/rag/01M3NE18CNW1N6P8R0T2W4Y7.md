RAG 是**离线建索引、在线做检索**的两段流水线：

```
离线（文档 → 索引）：
  加载清洗（去页眉/转 markdown）→ 分块（chunk）→ 逐块算 embedding → 存向量库（带原文与元数据）

在线（问题 → 回答）：
  问题 → embedding → 向量检索 top-k（粗召回，20-50 块）
       → 重排 rerank（精排模型细读，留 3-5 块）
       → 组装 prompt：资料 + 「仅依据资料回答，标注引用」
       → 生成 → 引用校验（断言能对上原文才放行）
```

**问题多在离线段**：垃圾进垃圾出——PDF 表格解析稀碎、分块把表格腰斩、版本混乱（新旧文档同时在库），在线再精也救不回。**为什么要重排**：embedding 是「压缩成单向量比相似度」的粗召回（快但糙），rerank 模型把「问题+文档」一起细读打分（准但慢）——粗召回保覆盖、精排保精度，两级漏斗是性价比结构。

**术语速查**：两段流水线=离线索引在线检索|粗召回+精排=两级漏斗|仅依据资料=忠实性的 prompt 侧防线
