三者是「**状态放哪**」的三档答案：

- **Cookie**：浏览器存储+**自动携带**的机制（是容器不是方案）——裸放用户信息不可行，配合 Session/JWT 才有意义。属性防线：HttpOnly（防 JS 窃取）/ Secure（仅 HTTPS）/ SameSite（防 CSRF）；
- **Session**：状态在**服务端**（内存/redis），Cookie 只存一个 sessionId。优：可随时踢人、数据不外泄；劣：**每请求一次存储查询**，集群要**粘性路由或集中存储**（redis 共享 session）；
- **JWT**：签名保证「**自证**」——payload+签名发还客户端，服务端**无状态验签即认**。天然适配微服务/跨域/APP。三个代价：**无法主动失效**（签发到过期前一直有效）、payload **只编码不加密**、体积随声明变大每请求都背。

**工业折中**：**access token 短命（15 分钟）+ refresh token 长命换发**——泄露窗口小；需要「立刻踢人」的再补 **redis 黑名单**（登出/改密写入 jti）——本质是给无状态方案**买回一点状态**。

**术语速查**：自动携带=Cookie 的本职｜自证=验签不查库｜黑名单=给 JWT 补的状态补丁
