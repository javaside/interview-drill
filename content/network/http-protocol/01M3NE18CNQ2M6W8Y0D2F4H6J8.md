别背「GET 快 POST 慢」「GET 不能带 body」这类表层——**根子是语义契约**：

| 维度 | GET | POST |
|---|---|---|
| 语义 | **读取资源**——安全（不改状态）、**幂等**（发几次结果同） | **提交处理**——不安全、不幂等（两次下单=两笔订单） |
| 参数 | URL 查询串（长度限制来自**浏览器/服务器实现**，非协议） | 请求体（支持任意 Content-Type） |
| 缓存 | 可缓存、可收藏、可留浏览器历史 | 默认不缓存 |
| 语义外送 | 会被爬虫/预加载触发（安全≠可滥用：删除操作别用 GET） | 不会被预取误触 |

两个纠偏：①**「POST 更安全」是错觉**——明文 HTTP 下两者全裸，body 只是没显现在地址栏；②幂等是**重试的许可证**：网络超时后 GET 可以放心重发，POST 重发就可能重复下单（幂等键才能救）。

**术语速查**：安全=不改服务端状态｜幂等=重复执行结果不变｜幂等键=防重的业务编号

<!--advanced-->
PUT（幂等的整体替换）与 PATCH（部分更新）的语义边界。RESTful 语义滥用（全 POST 的 RPC 风格）损失的是 HTTP 生态：缓存/幂等/重试/日志审计全部失效。HTTP/2 里 GET 带 body 被明确禁止（实现兼容性）。
