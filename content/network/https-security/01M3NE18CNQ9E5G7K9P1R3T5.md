证书解决的问题是：**你怎么知道手里这个公钥真的是银行的，而不是中间人的？** 答案是引入**公证处（CA）**：

```
根 CA（私有密钥离线锁在库房，公钥预装在 OS/浏览器）
  └─ 用根私钥签发 中间 CA 证书（业务层——方便吊销与分域）
       └─ 用中间 CA 私钥签发 网站证书（域名 + 网站公钥 + 有效期）
```

浏览器验证时**逆向走链**：拿中间 CA 公钥验网站证书签名 → 拿根 CA 公钥验中间 CA 签名 → **根公钥在本机信任库里找到锚点** → 整条链可信。任何一环验签失败/域名不匹配（SAN 列表）/过期 → 红色警告。

**为什么分层**：根是全局信任的命根子（离线保存、极少使用）；日常签发全在中间 CA——**出了事故吊销中间层，不伤根**。CA 被黑/作恶（历史上的 DigiNotar 事件）的防御：**证书透明度 CT 日志**（所有签发公开可审计，浏览器只认有 SCT 证明的证书）+ HSTS + 证书钉扎。

**术语速查**：CA=公钥的公证处｜信任锚=本机预装的根｜CT=签发行为的公开账本
