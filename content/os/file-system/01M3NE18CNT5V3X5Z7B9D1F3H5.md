**fd（file descriptor）**是进程里「打开的文件」的**票据号**——一个整数，对着内核的打开文件表。出生自带三张：**0 标准输入、1 标准输出、2 标准错误**。

**重定向/管道不过是「换票据指向」**——shell 在 fork+exec 之前把 fd 接好：

```
cmd > file       关 1 号 → 指向 file        （exec 继承）
cmd 2>&1         2 号改指 1 号当前的去处    （顺序敏感：先 > 再 2>&1）
cmd | cmd2       内核建管道：左的 1 号接写端，右的 0 号接读端
```

**「一切皆文件」**的统一接口：普通文件、socket、管道、终端、设备——**全是 fd，全用 read/write**——所以 IO 多路复用（epoll）能一视同仁地候一大批；网络连接数限制本质也是 **fd 上限**（`ulimit -n`——C10K 时代的真凶）。

**2>&1 的顺序坑**：`cmd > f 2>&1`（stderr 跟着 stdout 进 f）vs `cmd 2>&1 > f`（stderr 跟着**当时的** stdout=终端，只有 stdout 进 f）——重定向按从左到右执行，改的是「票据当前指向」。

**术语速查**：fd=开文件的票据|重定向=换指向|继承=子进程拿到同一套票
