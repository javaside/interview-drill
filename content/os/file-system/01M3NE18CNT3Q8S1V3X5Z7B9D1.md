**write() 的返回只代表「进了页缓存」**——从这条快车道到磁盘铁底，隔着几步：

```
write(buf) ──▶ 页缓存（内存，掉电即失）── write() 到此返回！
                  │ 脏页积累，内核后台 writeback 慢悠悠刷
                  ▼
              块层/IO 调度 ──▶ 磁盘缓存 ──▶ 盘片/NAND ── 这才叫落盘
```

**掉电安全性**只由 **fsync** 保证：它**同步逼内核把该文件的脏页+元数据刷穿**到持久介质，返回才表示「现在断电也不丢」。代价是**毫秒级+吃 IO**——这就是数据库每次事务提交 fsync 的成本（WAL 的意义：把随机写转成一次顺序 fsync）。

**fsync vs fdatasync**：前者连**元数据**（大小/时间）一起刷，后者只刷数据（文件大小不变时）——少一次元数据 IO，DB 引擎普遍用 fdatasync。**Redis 的 everysec**：主线程写 AOF 缓冲，后台线程**每秒 fsync 一次**——掉电最多丢这 1 秒窗口的来源。

**术语速查**：write 返回=进了内存|writeback=后台慢慢刷|fsync=逼到铁底
