经典运维夜袭：`rm` 掉几十 G 日志，`df` 纹丝不动——**Unix 的删除只是「撕掉目录里的名字」**，inode 还有**活着的 fd 引用**（引用计数没归零），数据块就还挂在它名下；进程照常能通过已打开的 fd 读写这块「无名文件」。**du 按目录树扫描自然看不见它**（没名字了），**df 按块分配统计照样算**——两者口径差就是这些「幽灵文件」。

**处置三板斧**：

```
lsof +L1 | grep deleted      # 找到握着已删文件的进程与 fd
kill -USR1 <nginx pid>       # 让它 reopen（日志库支持的话）——inode 归零、空间立放
# 不支持 reopen 的只能择机重启进程
```

**预防姿势**：日志轮转用 **copytruncate**（复制后截断原文件——fd 不变）或**轮转后给进程发信号 reopen**（nginx USR1 / logrotate 的 sharedscripts+postrotate）。**切忌**「gzip 一个正被写的文件」——压缩的是半份内容且原 fd 依旧占空间，**先轮转再压缩**。

**术语速查**：撕名字不销户=Unix 删除语义|幽灵文件=deleted 但被握着|reopen=换新文件旧票据
