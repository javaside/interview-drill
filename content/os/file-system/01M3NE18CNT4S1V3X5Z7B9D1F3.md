文件系统崩溃的痛点：**元数据改到一半断电**（目录加了一半/块指针改了一半）——重启 fsck 全盘扫描（小时级），修不好就丢文件。**ext4 的解法=写前日志（write-ahead journal）**：

```
commit：① 把「要改什么」记进日志区（环形）
        ② checkpoint：照着日志真正改数据区
        ③ 日志标记已完成
掉电恢复：日志里已 commit 未 checkpoint → 重放（接着做完）
          写到一半没 commit → 丢弃（当没发生）
```

**三种日志模式**（数据要不要也进日志）：

| 模式 | 日志内容 | 速度 | 安全 |
|---|---|---|---|
| journal | **元数据+数据**都双写 | 慢 | 最高（掉电连文件内容都不丢） |
| **ordered（默认）** | 只元数据；**保证数据先落**再提交元数据 | 中 | 元数据一致+数据不张冠李戴 |
| writeback | 只元数据，数据乱序 | 快 | 可能出现「新文件旧内容」 |

**与 DB 的同构**：WAL/redo log 一模一样的思想——**先记后做，重放到底**（MySQL 的 redo、PG 的 WAL——把「随机改页」化成「顺序追加+重放」）。

**术语速查**：先记后做=日志的骨架|重放=接续做完|ordered=数据先行的折中
