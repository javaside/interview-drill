**inode 是文件的「身份证+地址簿」**：元数据（大小/权限/三个时间）与**数据块指针**住 inode；**文件名不在 inode 里**——目录只是一个「**文件名→inode 号**」的映射表。

**两种链接**：

```
硬链接：ln a.txt b.txt    两个目录项 → 同一个 inode（链接数 2）
  删 a.txt：链接数 1，inode 与数据安然无恙；两个都删才真释放
软链接：ln -s a.txt s.txt  s.txt 是独立小文件，内容是字符串「a.txt」
  删 a.txt：s.txt 变悬空（dangling），访问报 No such file
```

**限制的由来**：硬链本质是「目录表加一行映射」——**跨不了文件系统**（inode 号只在本盘内唯一）、不给目录用（防成环）。软链存的是路径字符串——跨盘跨目录随便指，代价是要**多跳一次解析**且会悬空。

**两个实战推理**：①**「删了文件 df 没释放」**：有进程还握着这文件的 fd——inode 引用未归零（`lsof | grep deleted` 找到它，重启或 close 才真释放——日志轮转的经典坑）；②**同盘 mv 瞬间完成**：只改目录项（映射表挪一行），数据块一个不动——跨盘 mv 才是真复制。

**术语速查**：目录=名字→inode 的账本|链接计数=还剩几个名字|悬空=软链指向空气
