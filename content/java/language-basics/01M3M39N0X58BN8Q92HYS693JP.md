`Integer a = 100; b = 100;` 时 `a == b` 是 **true**；换成 200 就变 **false**——这不是玄学，是**缓存**：

- 自动装箱 `Integer.valueOf(x)` 对 **-128 ~ 127** 范围的值返回**同一个缓存对象**（这个小区间的小整数太常用，复用省内存）；
- 范围外每次 new 新对象 → == 比 address → false。

结论：**包装类之间的比较永远用 equals**，== 的「碰巧为 true」是陷阱不是特性。`new Integer(100)` 则完全绕开缓存（且此构造器已废弃）。

**术语速查**：自动装箱=基本值自动变包装对象｜IntegerCache=小整数复用池｜缓存区间=-128~127

<!--advanced-->
规范要求 cache 至少 [-128,127]，上界可由系统属性扩展。Byte/Short/Long 缓存同区间（Long 不可调）；Boolean 两值；Character 到 127；Float/Double 无缓存。比较统一走 equals 或先拆箱。
