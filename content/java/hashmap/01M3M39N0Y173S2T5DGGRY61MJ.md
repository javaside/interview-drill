1.7 的经典事故：**并发扩容 + 头插法 = 环形链**。

两个线程同时 resize，你搬一个节点我搬一个节点——头插法（每次把节点**插到链头**，顺序反转）在交错执行下，两个节点可能互指成**环**。此后任何 get 落到这条链就**原地转圈，CPU 打满**。

1.8 的修复：改**尾插**（保持原序搬迁），环不再可能。但注意——**这只是修了死循环，没修线程安全**：并发 put 照样丢数据（两个写同一桶互相覆盖）。需要并发就 ConcurrentHashMap，没有例外。

**术语速查**：头插=新节点插链头（顺序反转）｜环形链=next 成环，遍历出不来｜尾插=接链尾（原序）

<!--advanced-->
transfer 的 next 指针交错写回是成环机制（e.next = newTable[i] 在两线程的重入时序下形成交叉引用）。8 的 lo/hi 拆链从算法上消除反转。并发丢数据：两个 put 同桶后写覆盖先写（无 lost update 检测）。resize/树化/退化多个结构修改点均无同步。
