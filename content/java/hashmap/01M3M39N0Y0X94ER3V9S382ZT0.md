一个 HashMap = **一个大数组**，每个槽位挂一条**小链表**（冲突的键排队），链太长（≥8）就升级成**红黑树**：

```
table[i] → k1 → k2 → k3 → …（冲突链）
        → 树节点（长链的进化形态，查找 O(log n)）
```

- **定位**：key 的 hash 与 `(n-1)` 按位与 → 数组下标（容量是 2 的幂，位运算**等价取模但更快**）；
- **树化**：链长 ≥8 且数组容量 ≥64 → 变红黑树，最坏查找从 O(n) 救回 **O(log n)**；树缩到 6 又**退回链表**（中间隔 2，防止在边界来回切换抖动）。

**术语速查**：桶=数组的槽位｜冲突=两个 key 落进同一桶｜树化=长链升级成树

泊松分布论证：良好 hash 下链长到 8 的概率约千万分之六——树化是兜底而非常态（攻击或劣质 hashCode 才常态触发）。TreeNode 体积两倍于 Node，退化阈值 6 留滞回带。tableSizeFor 保证任意初始容量向上取 2 的幂。
