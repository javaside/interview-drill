# UI 层实现计划（计划 4b/5）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 `src/app` 的 UI 层——两屏刷题主循环（题目+选项 → 即时判分+排期反馈）、知识地图（掌握度环 + 块级选择 + 付费转化入口）、公开题目页 SEO（`q/[cardId]`）、设置屏；离线优先（idb 缓存下发物 + 提交队列，联网后经 `/api/sync` 回放），消费 4a 的 `/api/queue`·`/api/review`·`/api/sync`·`/api/settings`·`/api/blocks`。

**Architecture:** UI 逻辑全部下沉到**可单测的纯模块**（客户端判分复用 `lib/mastery`、提交队列 reducer、离线存储走接口抽象），React 组件是薄壳。**离线纪律（§8.3）**：客户端只消费计划、永不生成计划；断网时用下发的 `prepared.correctIndices` 本地判分出屏②反馈，把提交入队到 idb，联网后由 `/api/sync` 逐条重放。**同构一致性（§11）**：客户端判分与服务端判分共用同一套 `lib/mastery` 纯函数，同一输入在 Node 与 jsdom 跑出逐字节相同的 JSON。依赖仍严格单向 `app → server → lib`；组件不直接 import drizzle/pg，只经 API 客户端与纯模块。

**Tech Stack:** Next.js 15（App Router，client/server components）· React 19 · **Tailwind CSS**（用户裁决：原子类、无运行时、移动端快速布局）· **idb**（IndexedDB 的薄 Promise 包装，离线缓存与提交队列）· vitest 双 project（node 环境跑纯核 + jsdom 环境跑组件）· **@testing-library/react** + **@testing-library/user-event**（用户裁决：纯核优先 + 轻量组件测，不引 Playwright）。复用 `lib/mastery`（四型判分）、`lib/scheduler`（`LocalDate`/`diffDays`）。

## 全局约束（每个任务隐含遵守）

- **客户端永不生成计划（§8.3 核心规则）**：UI 只消费 `/api/queue` 下发的 `prepared` 变体与圆点序列；离线答错**不重排、不跑 `schedule()`**，只把提交入队，UI 显示「计划将在联网后更新」。`plan[]` 唯一写者是服务端——违反即缺陷。
- **幂等 submissionId**：每次提交在客户端铸造一个 ULID 作 `submissionId`（`ulid` 已在依赖），入队与重试都带同一个；服务端 `review_log` 唯一索引去重（4a 已实现）。客户端**绝不复用**同一 submissionId 表示两次不同作答。
- **本地判分只为屏②即时反馈，不落库**：离线用 `prepared.variants[reviewIndex].correctIndices` 本地判分渲染屏②；真正的 `s`/计划由服务端回放时权威计算。本地分与服务端分必须一致（§11 同构）——两者共用 `lib/mastery`，不得在客户端另写一套判分。
- **同构一致性（§11）**：客户端判分模块 `scoreLocal` 与服务端 `replay.scoreSubmission` 对同一 `(card, variant, submission)` 必须产出逐字节相同的 `Rational`。测试用同一夹具在 node project 与 jsdom project 各跑一遍断言相等。
- **不显示正确条数（§6 屏①）**：选项区提示语固定「勾出所有属于这道题的要点」，**不渲染**「选 N 项」「正确 3 条」之类；选项总数恒 9（atomic 4），由 `prepared` 决定，UI 不得据选项数反推答案数。
- **空勾选不允许提交（§6）**：屏① 提交按钮在零勾选时禁用（多选/判断型）；atomic 未选禁用。前端拦截空提交，不写 `review_log`（不发请求，或按跳过处理）。
- **圆点序列画已落盘计划（§6/§6.1）**：屏② 的圆点 = `ReviewResult.remainingPlan`（绝对日期，末尾为面试日红点）。答对时圆点只会少一个、不重画；答错触发重排时 UI 必须**明说「计划已重排」**（`replanned=true`），不得默默换一排圆点。
- **今日进度分母当天不变（§6/§8.1）**：`progress.total` 来自服务端 `daily_session`，UI 直接显示 `done/total`，不在客户端自增分母。
- **SEO 页不做 cloaking（§7）**：`q/[cardId]` 对爬虫与用户**渲染完全相同**——题面 + `public` 要点（1-2 条）+「完整 N 条在 App 内」入口。**绝不**给爬虫看全文、给用户看付费墙。非 public 要点在此页永不出现。
- **产品内不得第二处付费提示（§10.1）**：转化入口只在知识地图（未解锁块显示真实题数不可进入）。刷题过程中**绝不**打断弹付费。
- **纯核纪律**：判分/队列/存储逻辑放 `src/app/**/lib`（或 `src/client`）纯模块，零 React、零 DOM 依赖（idb 实现除外，藏在接口后）；React 组件只做渲染与事件转发。SQL/HTTP 不出现在组件里。
- **依赖白名单（超出即违规）**：runtime 追加 `idb`；dev 追加 `tailwindcss` `postcss` `autoprefixer` `jsdom` `@testing-library/react` `@testing-library/user-event` `@testing-library/jest-dom`。其余沿用 4a 白名单。
- 组件测试用 jsdom；`import` 带 `.js` 后缀（lib/server 内部）；tsconfig 已开 `strict + noUncheckedIndexedAccess`。

## 数据与接口速览（消费 4a，照抄不发明）

```
GET  /api/queue  → DailyPayload {
       today: LocalDate; mode: 'sprint'|'maintenance';
       queue: Array<{ cardId; reason: 'overdue'|'due' }>;
       prepared: PreparedOptions[]  // { cardId; degradedTo; variants: PreparedVariant[] }
       progress: { done; total } }
     PreparedVariant = { optionTexts: string[]; correctIndices: number[]; distractorKeyPointIds: string[] }
POST /api/review { ...Submission } → ReviewResult {
       score; newS; nextReviewDate: LocalDate|null; remainingReviews;
       remainingPlan: LocalDate[]; replanned; maintenanceAdvanced;
       feedback: { correctChecked; wrongChecked; missed } }
POST /api/sync { submissions: Submission[] } → SyncResult {
       results: Array<{ submissionId; outcome: ReviewOutcome }>; duplicated: string[] }
POST /api/settings { readyByDate?: LocalDate|null; dailyCapacity? } → { replanned }
POST /api/blocks   { blockIds: string[] } → { paused; added }

Submission = { submissionId; cardId; reviewedAtMs } & (
   { kind:'selection'; selected:number[] } | { kind:'sequence'; order:number[] }
 | { kind:'judgment'; conclusion:0|1|2; selected:number[] } | { kind:'atomic'; selected:number })
```

**缺口（Task 2 补）**：`DailyPayload` 只带 `cardId` 与选项，**不带展示元数据**（题面、块名、频度、要点文本）。屏①/屏② 渲染需要它们——Task 2 在服务端把 `DailyPayload` 扩展出 `cards: CardView[]`（题面/块名/频度 + 要点文本供屏②染色），不改判分口径。
